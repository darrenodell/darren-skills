# Alpaca stock buying research

Use the bundled helper for market data and calculations; use current company filings and investor-relations sources for business, earnings and news analysis. The plugin reads prices and the market calendar only. It does not access accounts, holdings, options chains, or orders.

1. Resolve 1–10 US stock/ETF symbols. Produce general research when horizon, holdings, budget and risk limits are missing; do not invent personal context. Distinguish ETFs from operating companies and use the relevant risks. This is underlying stock research, not Wheel candidate scanning or options analysis; do not apply Wheel's RV20 minimum or start a Wheel scan.
2. Use a permanent output workspace outside the installed cache. The helper uses the same environment variables as Wheel: `ALPACA_KEY`, `ALPACA_SECRET`, optional `ALPACA_BASE_URL` (paper by default), and optional `ALPACA_DATA_URL` (official data host only). SDK-style `APCA_API_KEY_ID`/`APCA_API_SECRET_KEY` are aliases. Never print, embed, copy, or commit keys. Prefer inherited environment; have users enter credentials locally through a secure prompt if absent, not in chat. Read `references.md` only for connection setup, feed semantics, endpoints or local Wheel provenance.
3. Run `python3 <this-skill-directory>/scripts/fetch_snapshot.py --symbols AAPL MSFT --feed iex --out data` from the workspace. Substitute the user's symbols. IEX is the default used by Wheel; SIP is an explicit entitled choice. Never silently change feeds. If Python lacks IANA timezone data (common on Windows), use `python -m pip install tzdata` with the user's normal package-install permissions and retry.
4. Read `snapshot.json` and `chatgpt-packet.md`. Refresh if capture is over five minutes old at analysis start. Fail on missing required sessions, invalid bars or collection errors. Record the exact snapshot ID, analysis start, capture, trade/quote times, feed, adjustment and final included New York session date. The helper always excludes the current New York day, including after close. This conservative policy can intentionally omit an otherwise completed current session; disclose it.
5. Respect `quality.entry_price_eligible`. If false, continue only as clearly dated technical/general research and explicitly withhold a current entry-price judgment. During a regular session, refresh missing/stale trade or quote data where useful; stop claiming execution relevance if it remains unavailable. Outside regular hours, label observations historical or extended-hours and recheck before any new entry assessment. Retrieval freshness and trade/quote freshness are different.
6. Follow `report-prompt.md`. Use adjusted bars and trading-session returns/252-day volatility; do not recycle crypto's UTC calendar days or sqrt(365). IEX volume and quotes are not consolidated market-wide liquidity. Adjusted feed bars are not guaranteed regular-session auction closes or a full total-return model. Use primary current sources for earnings, guidance, valuation inputs, splits, dividends, material company news and catalysts. When source coverage is missing, label that part incomplete; do not call a technical screen a complete fundamental valuation.
7. Save timestamped Markdown with its snapshot ID under `reports/`. The selected reasoning setting belongs to the user's client; instructions cannot change it. If asked for more depth, use the available higher reasoning setting without promising a particular outcome. For regular ChatGPT without local execution, provide the packet and report prompt for upload; this plugin does not grant web chat local-file access.
8. After a valid report is saved, follow `../html-stock-report/SKILL.md` to create the self-contained HTML and request `stock-report-reviewer` inspection. Preserve the original Markdown, snapshot and qualifications. Return links to both formats and the inspection. If requested “Markdown only” or “data packet only”, skip presentation. If rendering/review fails, report the exact limitation and retain the usable source research.
